04. LazyColumn

Here is how to efficiently display massive lists in Jetpack Compose without melting your user's phone. Review this fully working implementation first, and consider how the UI knows exactly which item to draw as you scroll.

Simple Example​

@Composable
fun SimpleListExample(modifier: Modifier = Modifier) {
    val myItems = List(1000) { index -> "Element nr ${index + 1}" }

    LazyColumn(modifier = modifier.fillMaxSize()) {
        items(myItems) { item ->
            Text(
                text = item,
                modifier = Modifier.padding(16.dp)
            )
        }
    }
}

note

The items block is a declarative mechanism that takes our data list and tells Compose exactly how to draw a single element. Instead of manually writing a for loop, you simply provide the data and the UI template.

Kotlin Factory Function

Look closely at List(1000) { index -> "Element nr ${index + 1}" }. This is not a standard loop. It is a Kotlin factory function that instantly generates a list of 1,000 elements. The index starts at 0, so we add 1 to make it human-readable (Element nr 1, Element nr 2, etc.). It is a brilliant trick for mocking large datasets during development.

Advanced Example​

// 1. The Data Model
data class User(val id: String, val name: String, val email: String)

val sampleUsers = listOf(
    User("1", "Jan Kowalski", "jan.kowalski@example.com"),
    User("2", "Anna Nowak", "anna.nowak@example.com"),
    User("3", "Piotr Wiśniewski", "piotr.wisniewski@example.com"),
    User("4", "Katarzyna Wójcik", "katarzyna.wojcik@example.com"),
    User("5", "Michał Kamiński", "michal.kaminski@example.com")
)

// 2. The Main Activity
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            MaterialTheme {
                Scaffold(modifier = Modifier.fillMaxSize()) { innerPadding ->
                    AdvancedListExample(
                        users = sampleUsers,
                        modifier = Modifier.padding(innerPadding)
                    )
                }
            }
        }
    }
}

// 3. The Lazy List Implementation
@Composable
fun AdvancedListExample(users: List<User>, modifier: Modifier = Modifier) {
    LazyColumn(
        modifier = modifier,
        verticalArrangement = Arrangement.spacedBy(12.dp),
        contentPadding = PaddingValues(16.dp)
    ) {
        items(
            items = users,
            key = { user -> user.id }
        ) { user ->
            UserCard(user = user)
        }
    }
}

// 4. The Single Item UI
@Composable
fun UserCard(user: User, modifier: Modifier = Modifier) {
    Card(
        modifier = modifier.fillMaxWidth(),
        elevation = CardDefaults.cardElevation(defaultElevation = 4.dp),
        colors = CardDefaults.cardColors(containerColor = MaterialTheme.colorScheme.surfaceVariant)
    ) {
        Row(
            modifier = Modifier.padding(16.dp).fillMaxWidth(),
            verticalAlignment = Alignment.CenterVertically
        ) {
            Box(
                modifier = Modifier
                    .size(48.dp)
                    .clip(CircleShape)
                    .background(MaterialTheme.colorScheme.primary),
                contentAlignment = Alignment.Center
            ) {
                Text(
                    text = user.name.first().toString(),
                    color = MaterialTheme.colorScheme.onPrimary,
                    style = MaterialTheme.typography.titleMedium
                )
            }
            Spacer(modifier = Modifier.width(16.dp))
            Column {
                Text(text = user.name, style = MaterialTheme.typography.titleMedium, fontWeight = FontWeight.Bold)
                Text(text = user.email, style = MaterialTheme.typography.bodyMedium, color = MaterialTheme.colorScheme.onSurfaceVariant)
            }
        }
    }
}


Think about it: Look at the items block in AdvancedListExample. Why do we provide a key parameter instead of just letting Compose guess the order of the items?

The 4W2H Breakdown: Data Logistics​

To understand why LazyColumn is a massive upgrade over standard components, we must analyze how it handles data logistics using the 4W2H model.

  • 0. The Domain: WHAT are we processing?

    • Our list of 1,000 strings represents basic primitives, known as "The Sticky Note". They are short, simple pieces of information.
    • We are dealing with "The Organized Binder". The User data class represents a complex object containing specific properties like an ID, name, and email.

  • 1. State & Storage: WHERE does the data live?

    • Our myItems list is a local variable acting as "The Pocket". The developer keeps the data locally, and it disappears when the function finishes its scope.
    • Our sampleUsers list acts as "The Office". It operates as global state that can survive minor disturbances on the screen, unlike a private variable hidden in a chef's pocket.

  • 2. Evaluation Strategies: WHEN do we cook?

    • A standard Column uses "The All-You-Can-Eat Buffet" (The Eager Paradigm). It computes and loads all 1,000 elements at once, which requires a massive amount of RAM and slows down startup time. LazyColumn switches to "The Drive-Thru" (The Lazy Paradigm). The CPU generates data strictly on demand, only "cooking" the exact elements currently visible on the screen.
    • The device generates data strictly on demand. It only "fries up" the 5 UserCard components currently visible on screen, saving immense memory space.

  • 3. Data Flow: WHO sets the pace?

    • Scrolling down the list acts as "The Waiter" in a Pull Model. You (the user) control the pace, and the app synchronously pulls data from the source one by one as you scroll.

  • 4. Reactivity: HOW does the UI know?

    • Because we are using a standard immutable list rather than Compose State, this is "The Silent Ledger". If the data changes in the background, the UI will not automatically update.
    • Currently, our list is static ("The Silent Ledger"). If we wrapped our data in Compose State, it would become "The PA System". The interface would automatically and instantly swap items on the screen the moment the underlying data changes.

  • 5. Lifecycle: HOW LONG does it survive?

    • This static list currently lives in Short-term Memory. If the user rotates their screen, it is the equivalent of a waiter tripping over—the data is lost forever and recalculated from scratch.
    • Right now, the scroll position and list data live in Short-term Memory. If you rotate the phone, the app restarts and drops the data like a stumbling waiter.

LazyColumn Optimization​

The Theater Coatroom Metaphor Imagine a theater coatroom where a row of coats hangs:

  • Default Behavior (No Keys): The attendant hangs coats on hooks 1, 2, and 3, remembering them only by position. If the guest with coat #1 leaves, the attendant must shift all remaining coats one spot to the left. Coat #2 becomes coat #1. This breeds chaos and unnecessary work.
  • Advanced Approach (With Keys): The attendant pins a unique name tag (e.g., a database ID) to every coat. When someone takes their coat, the attendant does not shift the rest. The system knows exactly which coat is which, regardless of its position.

Evolution: Legacy XML vs. Jetpack Compose​

To appreciate LazyColumn, you must understand the nightmare it replaced. In the older Android View System, rendering a simple dynamic list required massive structural overhead.

FeatureLegacy Android (XML)Jetpack Compose
The ComponentRecyclerViewLazyColumn
Files Required4 (Activity, List XML, Item XML, Adapter)1 (A single Kotlin file)
Boilerplate CodeHigh. You had to manually write an Adapter and a ViewHolder to recycle memory.None. The items block handles memory recycling automatically under the hood.
PerformanceExcellent, but highly prone to human error during setup.Excellent, completely declarative, and fail-safe.

Summary & Next Steps​

We have successfully rendered a massive list using the Lazy Paradigm, ensuring the CPU only processes the UI elements currently visible on the screen. However, there is a catch: our data is only temporarily remembered, meaning a simple screen rotation will wipe it out completely.

Before we solve this by upgrading our architecture and moving our data to a safer place ("The Office" / Global State), we will explore the LazyRow component in the next lesson. It works just like LazyColumn, but is built for smooth, horizontally scrollable lists—perfect for elements like photo carousels and side-scrolling menus.
