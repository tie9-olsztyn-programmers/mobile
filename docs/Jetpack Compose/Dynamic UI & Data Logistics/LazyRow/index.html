05. LazyRow

In the previous lesson, we learned how to efficiently scroll vertically through thousands of items. But what if we want to build a horizontal swipe gallery, like a movie carousel or a row of profile avatars?

Here is how you build a memory-efficient horizontal list. Review this working implementation first, and consider how it handles screen constraints compared to a vertical list.


@Composable
fun HorizontalGalleryExample(modifier: Modifier = Modifier) {
    // 1. Our mock dataset
    val dogBreeds = listOf(
        "Owczarek podhalański",
        "Golden Retriever",
        "Siberian Husky",
        "Border Collie",
        "Doberman"
    )

    // 2. The Horizontal Lazy Container
    LazyRow(
        modifier = modifier.fillMaxWidth(),
        // Notice the difference: horizontalArrangement instead of verticalArrangement
        horizontalArrangement = Arrangement.spacedBy(16.dp),
        // We pad the left and right edges so cards don't stick to the screen bezel
        contentPadding = PaddingValues(horizontal = 24.dp)
    ) {

        items(dogBreeds) { breed ->
            Card(
                elevation = CardDefaults.cardElevation(defaultElevation = 4.dp),
                // We constrain the width and height of each card specifically
                modifier = Modifier.size(width = 160.dp, height = 200.dp),
                colors = CardDefaults.cardColors(
                    containerColor = Color(0xFF8BC34A)
                )
            ) {
                Box(modifier = Modifier.fillMaxSize().padding(16.dp)) {
                    Text(
                        text = breed,
                        style = MaterialTheme.typography.titleMedium
                    )
                }
            }
        }
    }
}

Think about it: If we changed the dataset from 5 strings to a massive list of 10,000 high-resolution images, what prevents the phone's memory from instantly overflowing and crashing the app?

The 4W2H Breakdown: Logistics of the Row​

To understand why our app doesn't crash, we must analyze the data logistics driving this component, referencing the established 4W2H framework.

  • 0. WHAT are we processing? Our dogBreeds list consists of simple strings, functioning as "The Sticky Note" (Primitives). They are short, simple pieces of information.
  • 1. WHERE does the data live? Because the list is defined directly inside our composable function, it acts as "The Pocket" (Local Variables). Only this function has access to it, and it disappears when the function completes.
  • 2. WHEN do we cook?
    • A standard Row would utilize "The Eager Paradigm" (The All-You-Can-Eat Buffet). It would calculate and load all items into RAM simultaneously.
    • LazyRow operates on "The Lazy Paradigm" (The Drive-Thru). The processor generates the UI components strictly on demand, waiting until the user explicitly scrolls left or right to render the next card.
  • 3. WHO sets the pace? Your thumb acts as "The Waiter" in a Pull Model. You control the scroll speed, synchronously pulling data from the source one item at a time.
  • 4. HOW does the UI know? Our dataset is a static val, acting as "The Silent Ledger". If the data changes in the background, the UI will not automatically update.
  • 5. HOW LONG does it survive? This list currently exists in Short-term Memory. If you rotate the device, it is the equivalent of the waiter tripping—the local data vanishes and the UI resets.

LazyRow vs LazyColumn: The Crucial Differences​

While they are siblings, LazyRow requires a slight shift in how you think about spatial constraints.

  1. The Arrangement Axis
  • In a LazyColumn, you separate items vertically: verticalArrangement = Arrangement.spacedBy(12.dp).
  • In a LazyRow, gravity shifts sideways. You must use horizontalArrangement to place gaps between your items from left to right.
  1. The Padding Geometry When building horizontal galleries, you want the first and last cards to sit slightly away from the phone's physical bezels, but you want them to scroll under the bezels smoothly. By applying contentPadding = PaddingValues(horizontal = 24.dp) directly to the LazyRow, you create a beautiful "safe zone" at the start and end of the list without breaking the continuous scroll effect.
tip

Always fix the width of your cards inside a LazyRow. If you use fillMaxWidth() on a child item inside a horizontal list, Compose won't know how wide to draw it, because a LazyRow has infinite width!

Evolution: Legacy XML vs. Jetpack Compose​

In the older Android View System, building a horizontal list was notoriously annoying. Let's look at the evolution.

FeatureLegacy Android (XML)Jetpack Compose
The ComponentRecyclerViewLazyRow
Orientation SetupYou had to write Java/Kotlin code to explicitly attach a LinearLayoutManager(context, LinearLayoutManager.HORIZONTAL, false).Just type LazyRow instead of LazyColumn. That's it.
Spacing & MarginsRequired creating complex math inside a custom ItemDecoration class just to add a gap between horizontal cards.horizontalArrangement = Arrangement.spacedBy(16.dp)
BoilerplateHigh. Adapters, XML layouts for the row, and ViewHolders.Zero. The items block handles memory recycling natively.

By simply changing one word (Column to Row), Jetpack Compose entirely restructures the memory recycling direction under the hood, sparing you from writing dozens of lines of configuration code.

Summary & Next Steps​

You have now mastered both dimensions of efficient UI layouts. With LazyRow, creating horizontal carousels, category chips, or image galleries requires just a few lines of declarative code—free from the adapter boilerplate and complex layout managers of the past.
