Project 03: Data Logistics (A First Look)

In the previous lesson, we learned about the payload—primitive data like Int or String. But an application rarely handles just one piece of data. Usually, we deal with hundreds, thousands, or even millions of items.

Before we learn how to write the code for large datasets, we need to understand the architecture of data flow. A common mistake in programming is mixing up where data lives, when it's processed, and how it travels.

Let's step away from the code for a moment and look at how a massive restaurant operates. This is exactly how your computer's RAM and CPU serve data. We need to answer three fundamental questions:

  • Where,
  • When,
  • Who.

1. Data Structures: The Warehouse (WHERE is the data?)​

Before you can cook, you need to store your ingredients. Data structures define how bits are physically or logically organized in the computer's RAM memory.

  • Linear Structures (The Aisle): Ingredients are placed sequentially on a long shelf, one after another. You walk down the aisle from start to finish.
    • Kotlin Examples: Array, List.
  • Non-Linear Structures (The Recipe Tree): Ingredients are organized in complex relationships, like a hierarchy of sub-recipes or a web of categories.
    • Kotlin Examples: Map, Set, Trees.

2. Evaluation Strategies: The Kitchen (WHEN do we cook?)​

This defines when the CPU actually does the work to process or calculate the data.

The Eager Paradigm (The All-You-Can-Eat Buffet)​

The chefs wake up at 4:00 AM and cook exactly 100 scrambled eggs and 50 pancakes. They put everything on huge tables before the first guest even wakes up.

  • How it works: The computer calculates and loads all the data at once. If you filter a list of 10,000 items, it processes all 10,000 before moving to the next line of code.
  • The Cost: It takes a lot of time upfront and requires a massive table (high RAM usage).
  • When to use it: Small, static datasets that need instant access.

The Lazy Paradigm (The Drive-Thru)​

When you pull up to the window, the burgers are not ready. The chef is waiting for your order. You say "I want one burger," and the chef cooks exactly one burger.

  • How it works: The computer does nothing until the application explicitly asks for the next item. It generates data strictly on demand.
  • The Cost: It saves a massive amount of table space (low RAM), but the app waits a millisecond for the CPU to "cook" each requested item.
  • When to use it: Processing massive datasets where loading everything at once would crash the application.
  • Kotlin Structure: Sequence.

3. Data Flow & Streams: The Delivery (WHO sets the pace?)​

A Stream is not a storage warehouse; it is the transportation system (the pipeline). Pipelines can be driven in two very different ways based on who controls the flow.

Sync Stream / Pull Model (The Waiter)​

You sit at the table. You are in control. You say, "Bring me the next dish," and the waiter brings it. You eat it, then ask for the next.

  • How it works: The application "pulls" data from a static source (like a large database) one by one, dragging it through lazy filters. You control the pace.
  • Kotlin Structure: Standard Kotlin Sequence chains.

Async Stream / Push Model (The Sushi Conveyor Belt)​

The chef makes random plates of sushi and puts them on a moving belt. You just sit there and watch. When a plate you like passes by, you react and grab it.

  • How it works: The application doesn't control when the data arrives. It sets up a listener and waits asynchronously. The outside world "pushes" new information whenever it wants.
  • When to use it: Listening to a Discord bot waiting for a / slash command, reading live temperature from a BME280 sensor, or reacting to UI button clicks in Jetpack Compose.
  • Kotlin Structure: Flow.

Summary Checklist​

Even without writing the complex code yet, as a software engineer, you must know how to choose the right tool for the job:

ConceptThe QuestionExamples & Tools
Data StructureWHERE is it stored?Linear (List), Non-linear (Map).
EvaluationWHEN is it computed?Eager (Buffet), Lazy (Drive-thru).
Flow (Pull)WHO controls the pace?You pull data when ready (Sync Streams).
Flow (Push)WHO controls the pace?Source pushes data to you (Async Flow).
What's Next?

For the next few lessons, we will focus exclusively on the Eager approach and Linear Structures. We will learn how to build arrays and lists (our "buffet tables") before moving on to the more advanced Drive-Thru and Conveyor Belt architectures.
